# =============================================================================
# 用途：开发方案第八章「测试样本与验收 fixture」。
#       阶段 2~8 的每一阶段验收、以及 tests/ 下的 pytest 用例，一律以这三个文件为准。
#
# 为什么样本必须"刻意脏"：
#       干净数据跑通不代表程序正确；真正会崩的是 BOM、GBK、Excel 序列号时间、
#       负株数、>100 盖度、长缺口这些脏数据。样本必须长期固定不变，
#       否则"上次能跑通"这个结论就失去意义。
#
# 重建方式（仅在需要恢复样本时执行，会覆盖现有文件）：
#       python tests/samples/_generate_samples.py
#       （_generate_samples.py 是一次性生成脚本，不属于业务代码，不影响冻结结构）

sample_quadrat.csv —— 样方群落数据
-----------------------------------------------------------------------------
编码/格式 ：UTF-8 带 BOM（前三字节 EF BB BF），逗号分隔
列名      ：样方号 / 物种 / 株数 / 胸径 / 盖度
规模      ：38 行 × 5 列（其中 2 行为刻意植入的完全重复行）
刻意植入的脏数据：
  1. 首列列名带 BOM：用 encoding="utf-8" 读取会得到 '\ufeff样方号'，
     必须用 utf-8-sig 才能得到 '样方号'          —— 验证避坑 1
  2. 株数为负：2 处（Q2 油松 = -3、Q4 辽东栎 = -1）
  3. 盖度 > 100：3 处（Q1 油松 = 108、Q2 辽东栎 = 118、Q3 山杏 = 121）
  4. 盖度 0-1 小数制与百分制混用：11 处 0-1 之间的取值（第 4~6 号样方的
     胡枝子/披针苔草/蒿类），以及 0-1 之外但 ≤100 的百分制取值 —— 验证避坑 6
  5. 完全重复行：2 处（Q2 山杏、Q4 胡枝子 各复制一行）
  6. 缺失值：株数 1 处、胸径 2 处、盖度 2 处（另有 18 行胸径天然缺失，
     因为灌木与草本本就无胸径，不属脏数据，不得当作缺失问题处理）
用途阶段  ：阶段 2（解析）、阶段 3（清洗）、阶段 4（指标计算：手工核算期望值）、阶段 5（绘图）

sample_sensor.xlsx —— 传感器时序数据
-----------------------------------------------------------------------------
编码/格式 ：xlsx，工作表名「传感器数据」
列名      ：时间 / 气温 / 相对湿度 / 土壤温度
规模      ：230 行 × 4 列（原设计 240 个逐时点，人为删除 10 点制造断测）
刻意植入的脏数据：
  1. 时间列为 Excel 序列号数字（float，如 45413.0 = 2024-05-01 00:00:00），
     必须按 origin="1899-12-30", unit="D" 转换          —— 验证避坑 1 的时间分支
  2. 单点突变值：气温 58.7 ℃、相对湿度 -15.0 %（孤立极值，
     用于验证 MAD/IQR 稳健检测能杀掉它，而不会误伤真实极值）—— 验证避坑 8
  3. 连续长缺口：第 100~109 行整行被删除 → 时间轴上出现 11 小时跳变，
     即"连续缺测 10 个点"，用于验证 max_gap=3 时这段缺口必须保留 NaN 不插值
                                                          —— 验证避坑 7
  4. 单列短缺口：气温连续 2 点 NaN、相对湿度 1 点 NaN、土壤温度连续 4 点 NaN，
     用于验证 max_gap 以内的线性插值能正常补值
  5. 乱序时间戳：第 50/51 行与第 80/81 行的时间互换（步长出现 2 处负值），
     用于验证解析后按时间升序排序
精度说明（实测踩坑，重建样本时勿改回 round(6)）：
  序列号保留双精度全部有效位。若对序列号做 round(6)，整点会产生 ±28.8 毫秒偏移，
  解析回来变成 01:00:00.028799，与"统一输出 YYYY-MM-DD HH:MM:SS"的规格冲突。
  按现状生成时，解析偏差 ≤1 微秒，解析器取整到秒即可完全消除。
用途阶段  ：阶段 2（时间容错解析）、阶段 3（插值/max_gap）、阶段 4（时序统计）、阶段 8（大数据量回归的基线参照）

sample_plain_gbk.txt —— 普通实验统计数据
-----------------------------------------------------------------------------
编码/格式 ：GB18030（兼容 GBK），制表符（\t）分隔，无扩展名信息可用
列名      ：处理组 / 重复 / 温度 / 株高 / 生物量
规模      ：20 行 × 5 列
验证点：
  1. 编码探测必须落到第三顺位 gb18030；用 utf-8 解码会直接失败
     （这不是缺陷，是刻意设计）                      —— 验证避坑 1
  2. 本文件不含任何时间列，解析器不得"自动补全"出整列 NaT
     —— 验证方案阶段 2 第 4 条"有条件补全"
  3. 含缺失值 2 处（株高、生物量各 1）与异常值 1 处（温度 = -40.0 ℃）
  4. 该文件与样方群落、传感器时序均不同类，用于验证"混合类型多选时必须分组提示"
     —— 验证避坑 11
用途阶段  ：阶段 2（编码探测/类型识别）、阶段 3（异常值处理）
